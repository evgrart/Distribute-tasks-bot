# Telegram-бот распределения задач ДМ

Бот читает четыре Google-таблицы ДМсистемы, строит черновик распределения задач и после подтверждения практика публикует его в нужную беседу. Он не изменяет плюсики, единицы, посещаемость или баллы.

Бот работает на отдельном сервере через Telegram long polling. Публичный домен, HTTPS, webhook и сервисный аккаунт Google не нужны. Доступ к Google Sheets выполняет маленький Apps Script API-мост от имени владельца таблиц.

## Как устроена система

```text
Telegram ← long polling → Node.js-бот → подписанный HTTPS GET → Apps Script → Google Sheets
                              ↓
                        data/state.json
```

- Node.js-бот принимает команды Telegram, рассчитывает распределение, хранит черновики и публикует подтверждённый текст.
- `AppsScriptBridge.gs` только читает центральную таблицу и 15 листов выбранного практика.
- Каждый запрос к мосту подписан HMAC-SHA256. Токен Telegram в Apps Script больше не хранится.
- `data/state.json` хранит Telegram offset, черновики и защиту от одновременного расчёта одной пары.

## Алгоритм распределения

Для выбранного практика и номера практики бот:

1. Берёт студентов этого практика с `Прод = Да`.
2. Для Артёма и Немата оставляет только студентов с `Присутствие = Да`. Для Рами посещаемость не проверяется.
3. Кандидат на задачу существует только при `+` в соответствующей ячейке.
4. Уже стоящая `1` означает состоявшийся выход: задача считается покрытой, а студент использовал один из двух выходов на этой паре.
5. `-` кандидатом и выходом не считается.
6. Наибольший приоритет — покрыть максимально возможное количество разных задач.
7. При одинаковом покрытии бот сначала раздаёт первые выходы разным студентам, а только потом вторые.
8. Далее проводится взвешенная лотерея: студент, у которого больше отмеченных `+` и `1` суммарно по всем 15 практикам, получает больший шанс, но не гарантированную победу.
9. Вес студента равен `(1 + S)^p`, где `S` — число решённых задач за семестр, а `p` задаётся настройкой `SOLVED_PRIORITY_POWER`. По умолчанию `p = 0.5`: при 4 и 24 решённых задачах более активный студент выигрывает примерно в 69% равных случаев, а не всегда.
10. Кнопка «Пересчитать» меняет seed и проводит лотерею заново, не ухудшая максимальное покрытие.

Реализация использует min-cost max-flow, поэтому не попадает в ловушку простого жадного алгоритма, когда ранний выбор лишает редкую задачу единственного кандидата.

## 1. Требования

- рабочая ДМсистема с заполненными ID четырёх Google-таблиц в `Code.gs`;
- Node.js 20 или новее на сервере;
- Telegram-бот от `@BotFather`;
- сервер с постоянным доступом в интернет;
- этот репозиторий должен быть приватным.

## 2. Настройка Apps Script API-моста

Откройте Apps Script-проект центральной таблицы, где уже находится рабочий `Code.gs`.

1. Удалите из проекта старый `TelegramBot.gs`, если он там остался. Его webhook больше не используется.
2. Создайте файл `AppsScriptBridge.gs` и вставьте содержимое одноимённого файла из этого репозитория.
3. Откройте **Project Settings → Script Properties**.
4. Добавьте свойство `BOT_BRIDGE_SECRET` со случайной строкой не короче 32 символов.
5. Сохраните проект и один раз запустите функцию `telegramBridgeTest`, выдав необходимые разрешения.
6. Нажмите **Deploy → New deployment → Web app**.
7. Выберите Execute as: **Me**, Who has access: **Anyone**.
8. Скопируйте URL, заканчивающийся на `/exec`.

Секрет можно создать на Linux:

```bash
openssl rand -hex 32
```

Этот же секрет потребуется серверу. Он не передаётся в URL: сервер отправляет только одноразовую HMAC-подпись. Повтор запроса и запрос старше пяти минут отклоняются.

После изменений в `AppsScriptBridge.gs` обновляйте существующее развёртывание: **Deploy → Manage deployments → Edit → New version → Deploy**.

### Количество задач по практикам

Задаётся в `Code.gs` общей таблицы, едино для всех трёх практиков:

```javascript
defaultTaskCount: 30,
practiceTaskCounts: { 1: 30, 2: 25, 3: 40 },
```

Нужна актуальная версия `Code.gs` с `practiceTaskCount_`, `assertPracticeTaskLayout_` и `plusLayout_(practitioner, practice)`. Обновите оба файла (`Code.gs` и `AppsScriptBridge.gs`) в одном Apps Script-проекте, затем в общей таблице нажмите **DM система → Применить количество задач**. После этого обновите существующее развёртывание через **New version**, сохранив URL. Обновлять развёртывание нужно также после последующих изменений конфига в `Code.gs`: `/exec` использует опубликованную версию.

Мост читает каждую практику со своей шириной, включая задачи после 30-й, и суммирует `+`/`1` за семестр по соответствующим диапазонам. Если число столбцов пока не соответствует конфигу, он возвращает сообщение о необходимости применить настройки. После обновления создайте новый черновик или нажмите «Пересчитать», чтобы не публиковать старое распределение. В `.env` количества задач не дублируются, серверный алгоритм получает их из моста.

## 3. Настройка сервера

```bash
cp .env.example .env
```

Заполните `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=новый_токен_от_BotFather
ALLOWED_USER_IDS=7435960767,123456789
ADMIN_USER_IDS=7435960767
TARGET_CHAT_IDS={"1":"-1001111111111","2":"-1002222222222","3":"-1003333333333"}
SHEETS_BRIDGE_URL=https://script.google.com/macros/s/.../exec
SHEETS_BRIDGE_SECRET=тот_же_секрет_что_в_BOT_BRIDGE_SECRET
DROP_PENDING_UPDATES_ON_START=true
SOLVED_PRIORITY_POWER=0.5
```

Соответствие номеров: `1` — Артём, `2` — Рами, `3` — Немат.

`SOLVED_PRIORITY_POWER` управляет силой предпочтения более активных студентов: `0` — чистый рандом, `0.5` — умеренный приоритет, `1` — сильный. Значения от `0` до `2` допустимы.

`ALLOWED_USER_IDS` — практики, которые могут строить черновики. `ADMIN_USER_IDS` дополнительно могут управлять чужими черновиками. Свой ID и ID беседы можно узнать командой `/id`.

Если токен когда-либо попадал на скриншот, в чат или Git, отзовите его через `@BotFather` командой `/revoke` и используйте новый.

## 4. Первый запуск

```bash
npm test
npm start
```

При первом запуске бот удалит старый webhook, при включённой настройке один раз очистит накопившуюся старую очередь, зарегистрирует команды и начнёт long polling. Одноразовое удаление запоминается в `data/state.json`, поэтому перезапуск не удалит новые сообщения. После первого запуска рекомендуется заменить `DROP_PENDING_UPDATES_ON_START` на `false`.

Для проверки отправьте боту в личном диалоге `/start`, затем `/preview 1 1`.

## 5. Запуск как systemd-службы

Создайте `/etc/systemd/system/dm-telegram-bot.service`:

```ini
[Unit]
Description=DM task distribution Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=dm-bot
WorkingDirectory=/opt/dm-telegram-bot
ExecStart=/usr/bin/node /opt/dm-telegram-bot/src/index.js
Restart=always
RestartSec=5
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dm-telegram-bot
sudo systemctl status dm-telegram-bot
journalctl -u dm-telegram-bot -f
```

Запускайте только один экземпляр бота: два процесса будут конкурировать за одну очередь Telegram.

## 6. Команды

- `/preview` — выбрать практика и практику кнопками;
- `/preview 1 6` — сразу создать черновик для Артёма, практики 6;
- `/repeat` — снова показать последний свежий черновик;
- `/reroll` — пересчитать последний черновик;
- `/id` — показать ID пользователя и текущего чата;
- `/help` — краткая справка.

Черновик показывается только в личном чате. «Опубликовать» отправляет в беседу ровно сохранённый текст без повторного расчёта.

## 7. Обновление

```bash
git pull
npm test
sudo systemctl restart dm-telegram-bot
```

Не удаляйте `data/state.json`: там находятся незавершённые черновики и Telegram offset. Файл исключён из Git.

## 8. Диагностика

### Бот молчит

Проверьте журнал службы, доступ сервера к `api.telegram.org` и убедитесь, что запущен ровно один процесс.

### Telegram сообщает про webhook

Long polling и webhook несовместимы. Бот сам вызывает `deleteWebhook` при старте. Перезапустите службу и проверьте токен.

### «Неверная подпись запроса»

`SHEETS_BRIDGE_SECRET` в `.env` должен полностью совпадать с `BOT_BRIDGE_SECRET` в Apps Script. Также проверьте системное время сервера.

### Мост вернул HTML вместо JSON

Используйте опубликованный URL `/exec`, не `/dev`. Развёртывание должно быть доступно `Anyone`. Встроенный клиент бота следует перенаправлениям Google автоматически.

### Изменения в таблице не видны сразу

Новый `/preview` принудительно читает свежие данные. Кэш на 15 секунд используется только при быстром пересчёте уже созданного черновика.

## 9. Тесты

```bash
npm test
npm run check
```

Тесты проверяют фиксированные приоритеты, ловушку жадного алгоритма, ограничение выходов, seed, сохранение состояния и 300 случайных графов сравнением с полным перебором максимального покрытия.
